# TDD 규칙

> **이 규칙은 Rigid — 상황에 맞게 변형하지 마라.**
> "이번만 예외", "이 경우엔 다르다"는 판단을 스스로 내리지 않는다. 예외가 필요하면 사용자에게 먼저 묻는다.

## 0. 우선순위

프로젝트의 `CLAUDE.md` 또는 `AGENTS.md`에 TDD 규칙이 있으면 **그 규칙을 우선**한다.
이 파일은 기본값(fallback)이며, 프로젝트 문서에 TDD 규칙이 없을 때만 적용한다.

## 1. 적용 기준

### 반드시 TDD를 적용한다

- **비즈니스 로직**: 계산, 검증, 상태 전이, 권한 판단
- **API**: 엔드포인트, 요청·응답 처리, 에러 매핑
- **유틸 함수**: 순수 함수, 데이터 변환, 파싱
- **버그 수정**: 실패하는 재현 테스트를 먼저 만든다

### TDD가 불필요하다

- **타입 정의**: `type`, `interface` 선언만 있는 파일
- **설정 파일**: 빌드, 린트, 환경 설정
- **순수 UI**: 스타일링과 레이아웃만 바꾸는 마크업
- **SQL**: 스키마와 마이그레이션 (쿼리 로직을 함수로 감싼 경우는 그 함수에 TDD 적용)

불확실하면 **적용한다**. 불필요 목록에 명확히 해당할 때만 건너뛴다.

## 2. RED → GREEN → REFACTOR

### RED: 실패하는 테스트를 먼저 쓴다

- **하나의 동작 = 하나의 테스트.** 여러 동작을 한 테스트에 묶지 않는다.
- 테스트를 쓴 뒤 **반드시 실행해서 실패를 확인한다.** 실행하지 않은 실패는 실패가 아니다.
- 실패 이유는 **"기능 미구현"**이어야 한다. 오타, import 실패, 문법 오류로 죽은 테스트는 RED가 아니다. 이런 경우 테스트를 고쳐 기능 미구현 실패가 나오도록 만든다.

### GREEN: 최소한의 코드로 통과시킨다

- 테스트를 통과시키는 **가장 적은 코드**만 쓴다.
- **YAGNI**: 지금 테스트가 요구하지 않는 분기, 옵션, 추상화를 추가하지 않는다.
- **신규 테스트와 기존 테스트 전부**가 통과하는지 확인한다. 기존 테스트가 깨지면 GREEN이 아니다.

### REFACTOR: 구조를 정리한다

- 중복 제거, 이름 개선, 헬퍼 추출을 한다.
- 각 변경 후 **테스트를 다시 실행해 green을 유지한다.**
- **새 동작을 추가하지 않는다.** 새 동작이 필요하면 RED로 돌아간다.

### 반복

다음 동작을 고른 뒤 **RED로 돌아간다.** 한 사이클에 여러 동작을 몰아서 구현하지 않는다.

## 3. 삭제 강제 규칙

- **테스트 전에 프로덕션 코드를 먼저 작성했다면, 그 코드를 삭제하고 RED부터 다시 시작한다.**
- 삭제한 코드를 "참고용"으로 남기거나, 테스트를 쓰면서 그대로 옮겨 붙이지 **않는다.** 옮겨 붙이면 테스트가 구현을 따라간 것이지 동작을 검증한 것이 아니다.
- 이 규칙은 **예외 없이** 적용한다.

## 4. 변명 차단표

| 변명 | 반론 |
|---|---|
| "너무 단순해서 테스트가 필요 없다" | 단순한 코드도 나중에 바뀐다. **단순할수록 테스트는 싸게 쓸 수 있다.** 쓰지 않을 이유가 되지 않는다. |
| "나중에 테스트를 추가하겠다" | **나중의 테스트는 구현을 확인하는 도장이 된다.** 실패를 본 적 없는 테스트는 아무것도 증명하지 않는다. 지금 쓴다. |
| "시간이 없다" | TDD는 디버깅 시간을 줄인다. 테스트 없이 빨리 만든 코드는 확인 과정에서 더 많은 시간을 쓴다. 시간이 없을수록 RED부터 시작한다. |
| "삭제하면 낭비다" | 이미 쓴 코드를 살리려고 테스트를 나중에 맞추면, 그 테스트는 **구현을 복사한 것**이 된다. 낭비를 줄이는 길은 삭제다. |
| "프로토타입이다, 나중에 다시 짠다" | 프로토타입이 프로덕션으로 넘어가는 경우가 가장 흔하다. **"나중에 다시 짠다"는 보통 다시 짜지 않는다.** 프로토타입에도 같은 규칙을 적용한다. |

## 5. 완료 체크

작업을 끝내기 전에 다음을 확인한다.

- [ ] 새 동작마다 실패를 본 테스트가 있다
- [ ] 실패 이유가 기능 미구현이었다
- [ ] 전체 테스트가 통과한다
- [ ] 테스트 없이 작성한 프로덕션 코드가 없다
